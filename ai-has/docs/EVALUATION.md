## Limitations (read before citing these numbers)

- Offline mode uses hashed local embeddings and keyword routing, not `text-embedding-3-small` / `gpt-4o-mini`. Live-LLM accuracy and latency will differ; the live function-calling path is not covered here.
- The dashboard's **Faithfulness / Relevance** scores are lexical-overlap heuristics (`_compute_rag_scores` in `backend/app/agent/orchestrator.py`), not LLM-judged, so they are not reported as accuracy evidence.
- The retrieval set is small and was written by the authors with the SOPs in view, so near-perfect scores are expected; treat it as a regression guard, not an independent benchmark. Add held-out queries from real users to measure generalisation.
- Out-of-scope rejection above is the retriever's score alone. End-to-end, the orchestrator also requires the absence of IT-domain terms before answering `out_of_scope` (see the 2/2 out-of-scope synthetic cases), but a retriever-only cut-off still lets some off-topic queries through.
- Latency is measured in-process on a developer machine/CI runner; it excludes network and TLS and serialises on one event loop.
